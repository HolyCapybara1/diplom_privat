# ТЕХНОЛОГИЧЕСКИЙ СТЕК

## Фронтенд (клиентская часть)
- **HTML5** — структура и разметка страниц, семантические теги
- **CSS3** — стили, CSS Custom Properties (переменные), Grid, Flexbox, адаптивность
- **JavaScript ES6+** — логика, async/await, fetch API, localStorage
- **Chart.js 4.4.0** — графики на дашборде администратора
- **EmailJS** — отправка заказов на email (подключён, настраивается)

## Бэкенд (серверная часть)
- **PHP 8** — REST API, обработка запросов, бизнес-логика
- **MySQL 8** — реляционная база данных
- **Apache2** — веб-сервер, раздаёт файлы пользователям
- **PDO** — безопасная работа с БД через подготовленные запросы (защита от SQL-инъекций)

## Принцип работы архитектуры
```
Браузер пользователя  ←→  Apache + PHP (сервер)  ←→  MySQL (база данных)
  HTML/CSS/JS               REST API                   Таблицы данных
  localStorage              Сессии (cookies)
```

Браузер показывает страницу и управляет корзиной самостоятельно.
Когда нужно получить или сохранить данные — JavaScript отправляет
HTTP-запрос на PHP. PHP работает с MySQL и возвращает JSON-ответ.

| Поле | Тип | Описание |
|---|---|---|
| id | INT AUTO_INCREMENT | Первичный ключ |
| user_id | INT NULL FK→USERS | Пользователь (NULL если гость) |
| order_num | VARCHAR(20) | Номер заказа для отображения |
| date | VARCHAR(50) | Дата оформления |
| status | VARCHAR(50) | Новый / В обработке / Выполнен / Отменён |

| address | TEXT | Адрес доставки |

| phone | VARCHAR(50) | Телефон |
| email | VARCHAR(255) | Email |
| comment | TEXT | Комментарий к заказу |
| created_at | TIMESTAMP | Дата создания |

## Связи между таблицами
- **USERS → ORDERS**: один ко многим. ORDERS.user_id — внешний ключ на USERS.id. ON DELETE SET NULL (если удалить пользователя — заказы остаются, user_id становится NULL)
- **PRODUCTS ↔ ORDERS**: логическая связь через JSON. В момент оформления заказа данные о товарах копируются в поле items таблицы ORDERS. Жёсткой связи нет намеренно — чтобы удаление товара из каталога не ломало историю заказов.

# PHP REST API

Все эндпоинты возвращают JSON:
- Успех: `{"ok": true, "data": ...}`
- Ошибка: `{"ok": false, "error": "текст ошибки"}`

Авторизация через PHP-сессии (cookies). Все fetch-запросы с фронтенда используют `credentials: 'include'`.

## Эндпоинты авторизации /api/auth/
| Метод | URL | Описание |
|---|---|---|
| POST | register.php | Регистрация. Проверка дублей email, password_hash(), создание сессии |
| POST | login.php | Вход. password_verify(). Особый случай: admin/admin123 → сессия администратора |
| POST | logout.php | Выход. session_destroy() |
| GET | me.php | Текущий пользователь из сессии или null |
| PUT | profile.php | Обновить имя и телефон |

## Эндпоинты товаров /api/products/
| Метод | URL | Описание |
|---|---|---|
| GET | index.php | Все товары из MySQL, поля маппируются в camelCase |
| POST | store.php | Добавить товар. Только admin (require_admin()) |
| PUT | update.php?id=X | Редактировать товар. Только admin |
| DELETE | destroy.php?id=X | Удалить товар. Только admin |

## Эндпоинты заказов /api/orders/
| Метод | URL | Описание |
|---|---|---|
| GET | index.php | Заказы текущего пользователя (require_auth()) |
| POST | store.php | Оформить заказ. user_id берётся из сессии (nullable для гостей) |

## Эндпоинты администратора /api/admin/
| Метод | URL | Описание |
|---|---|---|
| GET | stats.php | Статистика: кол-во товаров, пользователей, заказов, выручка только по выполненным |
| GET | orders.php | Все заказы всех пользователей с LEFT JOIN users |
| PUT | order_status.php?id=X | Смена статуса заказа. Допустимые значения валидируются |
| GET | users.php | Список пользователей с кол-вом заказов и суммой |
| DELETE | delete_user.php?id=X | Удалить пользователя и его заказы |

# КАЛЬКУЛЯТОР СТОИМОСТИ — ГЛАВНЫЙ МОДУЛЬ

Работает полностью в браузере без обращения к серверу. Пересчёт мгновенный при каждом изменении параметра.

## 6 параметров расчёта

| Шаг | Параметр | Варианты | Влияние |
|---|---|---|---|
| 1 | Тип помещения | Квартира, Офис, Магазин, Производство | Коэффициент к итогу: 1.0 / 1.1 / 1.15 / 1.3 |
| 2 | Площадь | Ползунок 10–300 м² | Определяет нужную мощность (1 кВт на 10 м²) |
| 3 | Тип системы | Сплит, Кассетный, Канальный, Вентиляция | Базовая цена: 28000 / 65000 / 55000 / 35000 ₽ |
| 4 | Класс бренда | Эконом, Стандарт, Премиум | Множитель: 0.72 / 1.0 / 1.55 |
| 5 | Количество | Ползунок 1–10 шт | Умножает оборудование и услуги |
| 6 | Доп. услуги | Монтаж, ТО, Проектирование, Wi-Fi | Фиксированные суммы сверху |

## Формула расчёта
```
Мощность = Площадь × 0.1 кВт (округление до 2.5 кВт вверх)

Стоимость оборудования =
  Базовая цена типа системы
  × Коэффициент класса бренда
  × Коэффициент типа помещения
  × (Мощность / 2.5)
  × Количество единиц

Дополнительно:
  + Монтаж: 8 000 ₽ × количество
  + ТО: 3 500 ₽ × количество
  + Проектирование: 15 000 ₽ (разово)
  + Wi-Fi: 4 500 ₽ × количество

Итого = Оборудование + Услуги
Диапазон = от (Итого × 0.9) до (Итого × 1.2)
```

## Подбор товаров под расчёт
После расчёта внизу страницы система автоматически подбирает товары:
1. Фильтрует товары из БД по выбранному типу системы
2. Приоритизирует бренды выбранного класса (Эконом→Haier/LG, Стандарт→Samsung/Panasonic, Премиум→Daikin/Mitsubishi Electric)
3. Сортирует по близости цены к рассчитанному бюджету за единицу
4. Показывает топ-3 товара с кнопкой «В корзину»
5. Показывает карточки выбранных услуг с кнопкой «В корзину»

# КОРЗИНА И ОФОРМЛЕНИЕ ЗАКАЗА

## Как работает корзина
- Хранится в localStorage браузера
- Ключ: ki_cart_{userId} для авторизованных, ki_cart_guest для гостей
- Каждый товар: {id, name, price, emoji, category, qty}
- Можно добавлять товары И услуги (category = «Услуга»)

## Форма заказа
Поля: имя (обязательное), телефон (обязательное, валидация regex), email, адрес доставки, комментарий

## Валидация
- В реальном времени при вводе (событие input)
- При потере фокуса (событие blur)
- При попытке отправки

## После оформления
1. POST /api/orders/store.php — заказ сохраняется в MySQL
2. Корзина очищается
3. Показывается экран «Спасибо, {имя}!»
4. Заказ появляется в истории пользователя и в панели администратора

## Компоненты
- Карточки товаров с тенью и анимацией при наведении
- Badge-теги на карточках (Хит — красный, Новинка — зелёный, Акция — красный)
- Toast-уведомления (всплывают снизу на 3 секунды) при добавлении в корзину
- Модальные окна для деталей заказа и редактирования товаров
- Прогресс-бар в калькуляторе
- Адаптивное бургер-меню на мобильных

## Адаптивность
- Хедер: при ширине < 768px навигация скрывается, появляется бургер-кнопка
- Каталог: фильтры скрываются в боковую панель, открываются кнопкой
- Калькулятор: две колонки → одна колонка
- Сетка товаров: 3 колонки → 2 → 1

# ТИПИЧНЫЙ СЦЕНАРИЙ ИСПОЛЬЗОВАНИЯ

## Клиент
1. Открывает сайт → видит главную страницу с акционными товарами
2. Переходит в калькулятор → вводит параметры → получает расчёт стоимости
3. Видит рекомендованные товары и услуги → добавляет в корзину
4. Регистрируется / входит в аккаунт
5. Переходит в корзину → заполняет форму → оформляет заказ
6. В личном кабинете следит за статусом заказа

## Администратор
1. Входит через account.html (логин: admin, пароль: admin123) → попадает на admin.html
2. На дашборде видит статистику и последние заказы
3. В разделе «Заказы» меняет статусы, просматривает детали через модальное окно
4. В разделе «Каталог» добавляет, редактирует, удаляет товары
5. В разделе «История» видит выполненные заказы и итоговую выручку
6. В разделе «Пользователи» управляет аккаунтами
