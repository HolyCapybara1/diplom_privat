# Ключевые моменты кода веб-модуля «Климат-Инарс»

**Дипломная работа:** Разработка интерактивного веб-модуля автоматизированного расчёта стоимости услуг монтажа и обслуживания систем кондиционирования и вентиляции для ООО «Климат-Инарс»

---

## 1. Архитектура проекта

Проект реализован по архитектурному паттерну **клиент-сервер** с разделением на три уровня:

- **Клиентский уровень** — HTML5, CSS3, JavaScript (ES6+), без фреймворков
- **Серверный уровень** — PHP 8 REST API с маршрутизацией по файловой структуре
- **Уровень данных** — MySQL 8 с тремя связанными таблицами

Взаимодействие между клиентом и сервером происходит через HTTP-запросы в формате JSON. Клиент не перезагружает страницу — все данные загружаются асинхронно через Fetch API.

## 2. База данных: структура и связи

### 2.1 Таблица пользователей (users)

```sql
CREATE TABLE IF NOT EXISTS users (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    email       VARCHAR(150) NOT NULL UNIQUE,
    phone       VARCHAR(30),
    password    VARCHAR(255) NOT NULL,
    is_admin    TINYINT(1) DEFAULT 0,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

Поле `is_admin` — флаг администратора. Пароль хранится в виде bcrypt-хэша (функция `password_hash()`). Поле `email` имеет ограничение `UNIQUE` на уровне БД, что гарантирует уникальность учётных записей.

### 2.2 Таблица товаров (products)

```sql
CREATE TABLE IF NOT EXISTS products (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,
    category    VARCHAR(100) NOT NULL,
    brand       VARCHAR(100),
    price       DECIMAL(10,2) NOT NULL,
    description TEXT,
    specs       JSON,
    in_stock    TINYINT(1) DEFAULT 1,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

Поле `specs` имеет тип `JSON` — это позволяет хранить произвольные технические характеристики товара (мощность, площадь, класс энергопотребления) без изменения схемы таблицы при добавлении новых параметров.

### 2.3 Таблица заказов (orders)

```sql
CREATE TABLE IF NOT EXISTS orders (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    user_id     INT,
    name        VARCHAR(100) NOT NULL,
    phone       VARCHAR(30),
    email       VARCHAR(150),
    address     TEXT,
    comment     TEXT,
    items       JSON NOT NULL,
    total       DECIMAL(10,2) NOT NULL,
    status      VARCHAR(50) DEFAULT 'Новый',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

Ключевое архитектурное решение: состав заказа (поле `items`) хранится как **снимок данных** в формате JSON на момент оформления. Это означает, что если администратор впоследствии изменит или удалит товар из каталога, информация в уже созданном заказе останется неизменной — исторические данные не теряются.

Поле `user_id` — внешний ключ с `ON DELETE SET NULL`: если пользователь будет удалён, его заказы сохранятся в системе с `user_id = NULL`.

## 3. PHP REST API: конфигурация и вспомогательные функции

Файл `api/config.php` является ядром серверной части. В нём реализован паттерн **Singleton** для подключения к базе данных:

```php
<?php
session_start();

define('DB_HOST', 'localhost');
define('DB_NAME', 'klimat_inars');
define('DB_USER', 'ki_user');
define('DB_PASS', 'ki_password_2024');

function db(): PDO {
    static $pdo = null;
    if ($pdo === null) {
        $pdo = new PDO(
            "mysql:host=" . DB_HOST . ";dbname=" . DB_NAME . ";charset=utf8mb4",
            DB_USER, DB_PASS,
            [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
             PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC]
        );
    }
    return $pdo;
}
```

Переменная `$pdo` объявлена как `static` внутри функции — значит, при первом вызове создаётся подключение, при последующих вызовах возвращается тот же объект. Это экономит ресурсы сервера.

Все ответы API унифицированы через вспомогательные функции:

```php
function json_success($data = [], int $code = 200): void {
    http_response_code($code);
    header('Content-Type: application/json');
    echo json_encode(['ok' => true, 'data' => $data]);
    exit;
}

function json_error(string $msg, int $code = 400): void {
    http_response_code($code);
    header('Content-Type: application/json');
    echo json_encode(['ok' => false, 'error' => $msg]);
    exit;
}
```

Стандартизация ответов упрощает обработку на клиентской стороне: достаточно проверить поле `ok`.

### 3.1 Защита маршрутов

```php
function require_auth(): void {
    if (empty($_SESSION['user_id'])) {
        json_error('Необходима авторизация', 401);
    }
}

function require_admin(): void {
    if (empty($_SESSION['is_admin'])) {
        json_error('Доступ запрещён', 403);
    }
}
```

Функции-стражи `require_auth()` и `require_admin()` вызываются в начале защищённых эндпоинтов. Они используют PHP-сессии для проверки прав доступа и немедленно завершают выполнение с ошибкой, если проверка не пройдена.

## 4. Авторизация: безопасное хранение паролей

Файл `api/auth/login.php` реализует аутентификацию с использованием bcrypt:

```php
<?php
require_once '../config.php';

$body = get_body();
$email    = trim($body['email'] ?? '');
$password = trim($body['password'] ?? '');

// Специальный случай для администратора
if ($email === 'admin' && $password === 'admin123') {
    $_SESSION['user_id']  = 0;
    $_SESSION['is_admin'] = true;
    json_success(['id' => 0, 'name' => 'Администратор', 'is_admin' => true]);
}

// Обычный пользователь
$stmt = db()->prepare('SELECT * FROM users WHERE email = ? LIMIT 1');
$stmt->execute([$email]);
$user = $stmt->fetch();

if (!$user || !password_verify($password, $user['password'])) {
    json_error('Неверный email или пароль', 401);
}

$_SESSION['user_id'] = $user['id'];
json_success([
    'id'       => $user['id'],
    'name'     => $user['name'],
    'email'    => $user['email'],
    'is_admin' => (bool)$user['is_admin']
]);
```

Функция `password_verify()` безопасно сравнивает введённый пароль с bcrypt-хэшем из базы. Даже если злоумышленник получит дамп БД, восстановить оригинальные пароли методом прямого перебора будет крайне затруднительно из-за вычислительной сложности bcrypt.

Регистрация нового пользователя (`api/auth/register.php`):

```php
$hash = password_hash($password, PASSWORD_BCRYPT);
$stmt = db()->prepare(
    'INSERT INTO users (name, email, phone, password) VALUES (?,?,?,?)'
);
$stmt->execute([$name, $email, $phone, $hash]);
```

## 5. Клиентская авторизация (js/auth.js)

Модуль `Auth` отвечает за взаимодействие с API аутентификации:

```javascript
const Auth = {
    async login(email, password) {
        const res = await fetch('/api/auth/login.php', {
            method: 'POST',
            credentials: 'include',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ email, password })
        });
        const json = await res.json();
        if (!json.ok) throw new Error(json.error);

        localStorage.setItem('ki_user', JSON.stringify(json.data));

        if (json.data.is_admin) {
            localStorage.setItem('ki_admin_session', '1');
            window.location.href = 'admin.html';
        } else {
            window.location.href = 'index.html';
        }
        return json.data;
    },

    async logout() {
        await fetch('/api/auth/logout.php', {
            method: 'POST', credentials: 'include'
        });
        localStorage.removeItem('ki_user');
        localStorage.removeItem('ki_admin_session');
        window.location.href = 'index.html';
    },

    getCurrentUser() {
        const raw = localStorage.getItem('ki_user');
        return raw ? JSON.parse(raw) : null;
    }
};
```

Параметр `credentials: 'include'` обязателен: он указывает браузеру передавать cookies сессии при кросс-доменных запросах. Без него PHP-сессия не будет распознана сервером.

Данные пользователя кэшируются в `localStorage` для мгновенного доступа (например, отображения имени в шапке), а синхронизация с сервером выполняется через отдельный запрос `GET /api/auth/me.php`.

## 6. Корзина покупок (js/main.js)

Корзина хранится в `localStorage` и привязана к пользователю:

```javascript
const Cart = {
    _key() {
        const user = Auth.getCurrentUser();
        return user ? `ki_cart_${user.id}` : 'ki_cart_guest';
    },

    getItems() {
        return JSON.parse(localStorage.getItem(this._key()) || '[]');
    },

    addItem(product) {
        const items = this.getItems();
        const existing = items.find(i => i.id === product.id);
        if (existing) {
            existing.qty = (existing.qty || 1) + 1;
        } else {
            items.push({ ...product, qty: 1 });
        }
        localStorage.setItem(this._key(), JSON.stringify(items));
        this._updateBadge();
    },

    removeItem(id) {
        const items = this.getItems().filter(i => i.id !== id);
        localStorage.setItem(this._key(), JSON.stringify(items));
        this._updateBadge();
    },

    total() {
        return this.getItems().reduce(
            (sum, i) => sum + (i.price * (i.qty || 1)), 0
        );
    },

    _updateBadge() {
        const count = this.getItems().reduce(
            (s, i) => s + (i.qty || 1), 0
        );
        document.querySelectorAll('.cart-badge').forEach(
            el => el.textContent = count || ''
        );
    }
};
```

Ключ `ki_cart_${user.id}` гарантирует, что корзины разных пользователей не пересекаются. Гость использует ключ `ki_cart_guest`. При входе в систему товары из гостевой корзины можно перенести в пользовательскую.

## 7. Алгоритм калькулятора стоимости

Калькулятор (`calculator.html`) — центральная функция проекта. Расчёт выполняется по формуле:

```
Цена оборудования = S × k_type × (1 + 0.05 × (высота - 2.7)) / эффективность
Итоговая стоимость = Цена оборудования + Монтаж + НДС + Выезд специалиста
```

Реализация на JavaScript:

```javascript
function calc() {
    const S       = parseFloat(inputArea.value)   || 0;
    const H       = parseFloat(inputHeight.value) || 2.7;
    const people  = parseInt(inputPeople.value)   || 1;
    const devices = parseInt(inputDevices.value)  || 0;

    // Коэффициент по типу системы
    const typeCoeff = {
        split: 1.0,
        multi: 1.15,
        duct:  1.3,
        vrv:   1.8
    }[state.systemType] || 1.0;

    // Поправка на высоту потолков (стандарт 2.7 м)
    const heightAdj = 1 + 0.05 * Math.max(0, H - 2.7);

    // Базовая мощность и нагрузка от людей/техники
    const basePower  = S * 0.1;          // 100 Вт на кв.м
    const peoplePow  = people * 0.1;     // 100 Вт на человека
    const devicesPow = devices * 0.3;    // 300 Вт на устройство

    const totalKw = (basePower + peoplePow + devicesPow) * heightAdj;

    // Эффективность по классу энергопотребления
    const effMap = { 'A+++': 0.65, 'A++': 0.7, 'A+': 0.75, 'A': 0.8, 'B': 0.9 };
    const eff    = effMap[state.energyClass] || 0.8;

    const eqPrice      = totalKw * typeCoeff * 15000 / eff;
    const installPrice = eqPrice * 0.35;
    const vatAmount    = (eqPrice + installPrice) * 0.2;
    const visitFee     = state.urgency === 'express' ? 5000 : 2000;

    const total = eqPrice + installPrice + vatAmount + visitFee;

    // Отображение результатов
    document.getElementById('resEquipment').textContent =
        Math.round(eqPrice).toLocaleString('ru-RU') + ' ₽';
    document.getElementById('resInstall').textContent =
        Math.round(installPrice).toLocaleString('ru-RU') + ' ₽';
    document.getElementById('resTotal').textContent =
        Math.round(total).toLocaleString('ru-RU') + ' ₽';

    // Подбор рекомендаций после расчёта
    renderRecommendations(eqPrice / Math.max(1, units));
}
```

Коэффициент `typeCoeff` учитывает сложность системы: сплит-система — базовый случай (1.0), VRV-система — самая сложная и дорогая (1.8). НДС 20% начисляется на сумму оборудования и монтажа согласно налоговому законодательству РФ.

## 8. Алгоритм подбора товаров по бюджету

После расчёта стоимости система автоматически подбирает подходящие товары из каталога:

```javascript
function renderRecommendations(perUnitBudget) {
    const section = document.getElementById('recommendSection');

    // Загрузка актуального каталога из API
    const allProducts = window.PRODUCTS || [];

    // Фильтрация по типу системы
    const relevant = allProducts.filter(p => {
        if (state.systemType === 'split')
            return p.category === 'Сплит-системы';
        if (state.systemType === 'multi')
            return p.category === 'Мульти-сплит системы';
        if (state.systemType === 'duct')
            return p.category === 'Канальные системы';
        return true;
    });

    // Скоринговая система подбора
    const scored = relevant.map(p => {
        let score = 0;
        const priceDiff = Math.abs(p.price - perUnitBudget);
        const priceRatio = priceDiff / (perUnitBudget || 1);

        // Чем ближе цена к бюджету — тем выше балл
        if (priceRatio < 0.1) score += 50;
        else if (priceRatio < 0.2) score += 30;
        else if (priceRatio < 0.4) score += 15;

        // Совпадение бренда с предпочтением пользователя
        if (state.brandTier === 'premium' &&
            ['Daikin','Mitsubishi Electric'].includes(p.brand)) score += 20;
        if (state.brandTier === 'mid' &&
            ['LG','Samsung','Haier'].includes(p.brand)) score += 20;
        if (state.brandTier === 'budget' &&
            ['Ballu','Cooper&Hunter'].includes(p.brand)) score += 20;

        return { ...p, score };
    });

    // Топ-3 по скорингу
    const top3 = scored
        .sort((a, b) => b.score - a.score)
        .slice(0, 3);

    // Рендер карточек товаров
    const productsHtml = top3.map(p => renderProductCard(p)).join('');
    section.querySelector('#recommendProducts').innerHTML = productsHtml;
    attachCartButtons(section.querySelector('#recommendProducts'));
}
```

Скоринговая система даёт приоритет товарам, цена которых максимально близка к рассчитанному бюджету на единицу оборудования. Дополнительные баллы начисляются за соответствие ценовому сегменту бренда (премиум / средний / бюджетный).

## 9. Делегирование событий для кнопок корзины

Вместо навешивания обработчика на каждую кнопку отдельно используется **делегирование событий** — один обработчик на родительский контейнер:

```javascript
function attachCartButtons(container) {
    container.addEventListener('click', e => {
        // Кнопка добавления товара
        const btn = e.target.closest('.add-to-cart-btn');
        if (btn) {
            const id = btn.dataset.productId;
            const product = (window.PRODUCTS || PRODUCTS)
                .find(p => String(p.id) === String(id));
            if (product) {
                Cart.addItem(product);
                btn.textContent = '✓ В корзине';
                btn.classList.add('in-cart');
            }
            return;
        }

        // Кнопка добавления услуги
        const svcBtn = e.target.closest('.add-service-btn');
        if (svcBtn) {
            const id = svcBtn.dataset.serviceId;
            const svc = (window.SERVICES || SERVICES)
                .find(s => s.id === id);
            if (svc) {
                Cart.addItem({
                    id:            svc.id,
                    name:          svc.name,
                    price:         svc.basePrice,
                    emoji:         svc.emoji,
                    categoryLabel: 'Услуга'
                });
                svcBtn.textContent = '✓ В корзине';
                svcBtn.classList.add('in-cart');
            }
        }
    });
}
```

Преимущество делегирования: обработчик продолжает работать даже для элементов, которые были добавлены в DOM динамически после его установки. Это критично при асинхронной загрузке каталога из API.

## 11. Статистика и выручка в административной панели

Статистика рассчитывается на сервере в `api/admin/stats.php`:

```php
// Общая выручка только по выполненным заказам
$revenue = db()->query(
    "SELECT COALESCE(SUM(total), 0) FROM orders WHERE status = 'Выполнен'"
)->fetchColumn();

// Количество заказов по статусам
$completed  = db()->query(
    "SELECT COUNT(*) FROM orders WHERE status = 'Выполнен'"
)->fetchColumn();

$newOrders = db()->query(
    "SELECT COUNT(*) FROM orders WHERE status = 'Новый'"
)->fetchColumn();

// Динамика по месяцам (последние 6 месяцев)
$byMonth = db()->query("
    SELECT DATE_FORMAT(created_at, '%Y-%m') AS month,
           COUNT(*) AS cnt,
           SUM(total) AS revenue
    FROM orders
    WHERE created_at >= DATE_SUB(NOW(), INTERVAL 6 MONTH)
    GROUP BY month
    ORDER BY month ASC
")->fetchAll();

json_success([
    'products'   => $products,
    'users'      => $users,
    'orders'     => $orders,
    'revenue'    => (float)$revenue,
    'completed'  => (int)$completed,
    'new_orders' => (int)$newOrders,
    'by_month'   => $byMonth
]);
```

Выручка учитывается только по заказам со статусом «Выполнен», что соответствует реальной бизнес-логике: деньги считаются полученными только после завершения работ. График по месяцам строится с помощью библиотеки Chart.js.

## 13. Управление каталогом в административной панели

Добавление нового товара через API:

```javascript
async function saveProduct() {
    const id   = document.getElementById('prodId').value;
    const data = {
        name:        document.getElementById('prodName').value,
        category:    document.getElementById('prodCategory').value,
        brand:       document.getElementById('prodBrand').value,
        price:       parseFloat(document.getElementById('prodPrice').value),
        description: document.getElementById('prodDesc').value,
        in_stock:    document.getElementById('prodStock').checked ? 1 : 0
    };

    const url    = id ? `/api/products/update.php` : `/api/products/store.php`;
    const method = 'POST';
    if (id) data.id = id;

    const res  = await fetch(url, {
        method, credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data)
    });
    const json = await res.json();

    if (json.ok) {
        closeModal('productModal');
        renderCatalog();      // обновить таблицу
        // Синхронизировать window.PRODUCTS для калькулятора
        window.PRODUCTS = await fetch('/api/products/index.php')
            .then(r => r.json()).then(j => j.data);
    }
}
```

После сохранения товара глобальная переменная `window.PRODUCTS` обновляется свежими данными с сервера. Это обеспечивает синхронность: товары, добавленные администратором, сразу становятся доступны в калькуляторе и каталоге без перезагрузки страницы.

## 14. Переменная PRODUCTS: техническое решение

Критически важное архитектурное решение в файле `js/data.js`:

```javascript
// ВАЖНО: var, не const — чтобы window.PRODUCTS работало корректно
var PRODUCTS = [
    {
        id: 'p1', name: 'Daikin FTXB20C', category: 'Сплит-системы',
        brand: 'Daikin', price: 45000,
        description: 'Инверторный кондиционер, площадь до 20 кв.м',
        specs: { power: '2.0 кВт', area: '20 кв.м', class: 'A+' }
    },
    // ... остальные товары
];

// Синхронизация с глобальным пространством имён
window.PRODUCTS = PRODUCTS;
```

Использование `var` (а не `const` или `let`) принципиально: объявление `var` на верхнем уровне скрипта создаёт свойство объекта `window`. Это позволяет любому другому скрипту перезаписать `window.PRODUCTS = newData`, и все обращения к `window.PRODUCTS` получат актуальные данные. С `const` такое переназначение было бы невозможно.
